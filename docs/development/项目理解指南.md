**记住三件事就能开始读代码**：

1. **两层 Agent**：通用底座（GeneralAgent）+ 安糖业务（AnTangAgent）。子类只加业务，底座搞 ReAct。
2. **四种上下文**（重要，第二章会展开）：短期消息、会话摘要、跨轮 hidden state、长期记忆。每种存的位置和生命周期都不一样。

## 第二章 跟着一条消息走完全程

我们用一个具体例子贯穿全章：用户在前端发了"**我每次跑完步差不多 1 小时就降到 3.5**"。

跟着代码走一遍。每一步给你 **"做什么 + 为什么 + 在哪"** 三件事。

### 阶段 0：前端发出 SSE 请求

[src/frontend/src/apis/completion.ts] 把用户输入打包成 JSON `{dialog_id, user_input, glucose_context, file_url, file_name}`，POST 到 `/api/v1/completion`，用 `@microsoft/fetch-event-source` 接 SSE 流。

### 阶段 1：API 入口收单（[completion.py:80-99](../../src/backend/AnTang/api/v1/completion.py#L80-L99)）

```python
@router.post("/completion")
async def completion(*, req: CompletionReq, login_user = Depends(get_login_user)):
    runtime_config = await DialogService.get_dialog_runtime_config(req.dialog_id)
    agent_config = AgentConfig(**runtime_config["agent"])
    agent_config.user_id = login_user.user_id
    chat_agent = AnTangAgent(agent_config)
    await chat_agent.init_agent()      # ← 进入阶段 2
```

**做什么**：JWT 鉴权、根据 dialog_id 查它绑定的 agent，把 agent 的"装配清单"取出来。

**为什么是这种设计**：dialog 表里只存 agent_id，agent 配置在 agent 表里。这样换皮肤、换工具集，只动 agent 配置，dialog 不用改。

### 阶段 2：Agent 装配（[general_agent.py:191](../../src/backend/AnTang/core/agents/general_agent.py#L191)）

```python
async def init_agent(self):
    self.mcp_agent_as_tools = await self.setup_mcp_agent_as_tools()
    self.tools              = await self.setup_tools()
    self.skill_agent_as_tools = await self.setup_agent_skill_as_tools()
    await self.setup_language_model()
    self.middlewares = [EmitEventAgentMiddleware(...)]
    self.react_agent = create_agent(model, tools+mcp+skill, middleware, state_schema)
```

**做什么**：把 ID 列表展开成实际能用的对象。MCP server → 包成 tool；用户上传的 OpenAPI → 解析成 StructuredTool；技能子 Agent → 包成 tool；模型句柄取出。

**为什么**：业务层只需要"我有这些 ID"，Agent 层负责把它们变成 LangChain 可调用的东西。这一步是**慢的**（要查 DB、可能要 ping MCP），所以每次请求都重做一次（无状态）。

**重点抽象**：MCP/Skill/OpenAPI/内置工具最后都是 `BaseTool`。这就是为什么 ReAct 只需要一个 tools 列表，不关心来源。

### 阶段 3：拼上下文 4 件套（[completion.py:103-111](../../src/backend/AnTang/api/v1/completion.py#L103-L111)）

```python
short_history    = await HistoryService.get_short_term_messages(...)
history_summary  = await DialogService.get_dialog_history_summary(...)
previous_dialog_state = await _load_dialog_state_from_history(...)
# (长期记忆在阶段 4 并行召回)
```

这里出现了**本项目最容易让人晕的点**——"上下文"有四种来源：

| 来源 | 长什么样 | 谁负责维护 |
|---|---|---|
| **短期消息** | `[HumanMessage, AIMessage, ...]` 列表，是上次摘要之后的原文 | [HistoryService.get_short_term_messages](../../src/backend/AnTang/api/services/history.py#L76) |
| **会话摘要** | 一段中文摘要，把更早的消息压缩成一段 | [DialogService.update_dialog_summary](../../src/backend/AnTang/api/services/dialog.py#L134) |
| **DialogState** | `{stage, emotions, last_question}`，跨轮的轻量状态 | [completion.py:22 _load_dialog_state_from_history](../../src/backend/AnTang/api/v1/completion.py#L22) |
| **长期记忆** | 用户画像 + 命中的短事实 | [AnTangProfileService.recall_context](../../src/backend/AnTang/services/antang/profile.py#L73) |

短期 vs 摘要的**分界线**：`dialog.summary_last_time`。上次成功摘要时记一个时间戳，之后写入的进短期，之前的全部被压缩。

### 阶段 4：进入 AnTangAgent.astream（[antang_agent.py:266](../../src/backend/AnTang/core/agents/antang_agent.py#L266)）

```python
async def astream(self, *, user_input, short_history, history_summary, ...):
    # 4.1 缓存本轮临时上下文（工具闭包要用）
    self.current_glucose_context = glucose_context
    self.current_file_url = file_url
    
    # 4.2 启动并行任务
    recall_task = asyncio.create_task(
        AnTangProfileService.recall_context(user_id=..., query=user_input)
    )    # 长期记忆召回，~500ms
    
    analyzer_result = await light_analyzer.analyze(...)    # qwen-turbo, ~2s
    
    memory_ctx = await recall_task    # 一般已经 ready
    long_term_memory = self._format_long_term_memory_block(memory_ctx)
    
    # 4.3 拼 system prompt
    turn_prompt = build_turn_system_prompt_v2(base, analyzer_result, glucose_zone)
    system_prompt = build_completion_system_prompt(turn_prompt, history_summary, long_term_memory)
    
    # 4.4 组装 messages
    messages = [SystemMessage(system_prompt), *short_history, HumanMessage(本轮)]
    
    # 4.5 真正调 ReAct
    async for event in super().astream(messages):
        yield event
    
    # 4.6 跑完后计算新 dialog_state，yield 一个 hidden 事件
```

**重点**：

1. **轻量分析器**先跑一遍小模型（qwen-turbo），生成 4 栏备忘录（语境理解 / 核心担心 / 回复节奏 / 避免事项）+ 谨慎度。这相当于"主模型在认真回答之前先听一份分析师简报"。
2. **长期记忆召回**和分析器**并行**跑，召回快、分析器慢，所以等分析器跑完时召回早就 ready 了。
3. system prompt 是**分层叠加**的：
   ```
   人设基础
   + [本轮分析备忘录]            ← 来自 light_analyzer
   + [本轮语气提示]              ← 来自 caution_level
   + [安全提醒]                  ← 仅 severe_low 时
   + 📜 对话历史                 ← history_summary
   + 🧠 长期记忆                 ← long_term_memory
   ```
4. **HumanMessage 里只放本轮原话**（加血糖/图片说明），不掺历史。历史靠 `*short_history` 单独以 message 形式喂进去。

### 阶段 5：ReAct 循环（[general_agent.py:351](../../src/backend/AnTang/core/agents/general_agent.py#L351)）

```python
async for token, metadata in self.react_agent.astream(
    input={"messages": ..., "user_id": ...},
    stream_mode=["messages", "custom"],
):
    if token == "custom":     # 工具事件
        yield self.wrap_event(metadata)
    elif AIMessageChunk:       # 模型回复 token
        yield {"type": "response_chunk", "data": {"chunk": ..., "accumulated": ...}}
```

**ReAct 内部逻辑由 LangChain 实现**，项目代码不直接管。它会：
1. 把消息发给模型
2. 模型如果选择调工具 → middleware 触发 START 事件 → 跑工具 → 触发 END 事件 → 把工具结果加进消息列表 → 回到第 1 步
3. 模型直接输出文本 → 流式 yield 出 AIMessageChunk

**两种事件交错从这里流出去**，前端区别处理：
- `response_chunk` → 拼到主回复气泡里
- `event` → 渲染成工具调用卡片

### 阶段 6：finally 收尾（[completion.py:145-166](../../src/backend/AnTang/api/v1/completion.py#L145-L166)）

```python
finally:
    await chat_agent.finalize_turn(user_input, response_content)
    # ↑ 内部 asyncio.create_task 后台跑长期记忆写入，立即返回
    
    await HistoryService.save_chat_history(role="assistant", events=...)
    # ↑ 落 history 表
    
    await DialogService.update_dialog_summary(dialog_id, user_id)
    # ↑ 检查 token 累积超阈值就压缩，否则 noop
```

到这里一个完整的对话回合就结束了。前端 SSE 连接关闭，下一轮开始。

## 第三章 五个核心抽象

理解这五个抽象，就理解了为什么代码长这样。

### 抽象 1：两层 Agent（业务/底座分离）

```
GeneralAgent              ← 装配工：怎么把配置变成可运行 Agent
    └─ init_agent()         模型 + 工具 + 中间件 + ReAct
    └─ astream(messages)    流式输出 + 事件包装

AnTangAgent extends GeneralAgent    ← 业务：安糖怎么用 Agent
    └─ astream(...)         加分析器、加召回、拼 system prompt
    └─ finalize_turn()      写长期记忆
    └─ _build_antang_tools() 安糖专属工具
```

**好处**：以后想做"安心情绪"或别的子产品，只要再写一个 `XxxAgent extends GeneralAgent`，底座一行不用动。

### 抽象 2：Agent-as-Tool

主 Agent 调子 Agent 的方式不是直接调，而是**把子 Agent 包成一个 BaseTool**：

```python
# general_agent.py:setup_agent_skill_as_tools
@tool
async def some_skill_tool(query: str) -> str:
    sub_agent = SkillAgent(...)
    result = await sub_agent.run(query)
    return result
```

**为什么这样**：主 ReAct 只懂 BaseTool，所以无论是调 OpenAPI、调 MCP server、调子 Agent，都用同一种调用方式。子 Agent 内部可以有自己的 ReAct 循环、自己的工具集。

**MCP 同理**：每个 MCP server 都被包成一个独立的 tool（其实是一个迷你 ReAct agent，能自己挑 server 内的具体能力）。

### 抽象 3：四层上下文叠加

发给主模型的 prompt 是**逐层加上去的**，每一层有自己的责任：

```
┌─────────────────────────────────────────┐
│ DEFAULT_ANTANG_SYSTEM_PROMPT            │ ← 不变的人设
│ ─ 角色、语气、不能做的事                  │
├─────────────────────────────────────────┤
│ [本轮分析备忘录]                         │ ← 每轮新生成
│ [本轮语气提示]                           │
│ [安全提醒]                               │
├─────────────────────────────────────────┤
│ 📜 对话历史                              │ ← 慢慢累积，超阈值压缩
├─────────────────────────────────────────┤
│ 🧠 长期记忆                              │ ← 跨会话，按 user_id 召回
└─────────────────────────────────────────┘

+ short_history 作为独立 messages
+ HumanMessage(本轮)
```

每层是独立可关闭的：
- 关分析器：`config.yaml` `antang_light_analyzer.enabled: false`
- 关长期记忆：astream 里把 recall_task 注释掉
- 关历史摘要：dialog.summary 直接为 None
- 关 short_history：测试时直接传空列表

### 抽象 4：ReAct + Middleware（事件驱动）

工具调用的"前后通知"**不是在工具里 print**，而是 LangChain 的 `AgentMiddleware` 接口在工具调用前后插钩子，钩子里 yield 一个事件，事件通过 `stream_mode="custom"` 这个出口流出来。

```
模型决定调 web_search
    ↓
EmitEventAgentMiddleware.awrap_tool_call()
    ├─ yield START 事件 → 前端显示"🔍 联网搜索中..."
    ├─ 真正执行 web_search()
    └─ yield END 事件 → 前端把"中"改成"完成"
```

**好处**：工具实现者不用关心 UI；新增工具自动获得"事件卡"展示。

### 抽象 5：装配清单（AgentConfig）

```python
class AgentConfig(BaseModel):
    name: str
    llm_id: str | None
    tool_ids: list[str]
    skill_ids: list[str]
    mcp_ids: list[str]
    knowledge_ids: list[str]
    user_id: str | None       # 请求上下文注入
    ...
```

**它是 ID 集合，不是对象集合**。Agent 启动时把 ID 全展开成实际对象。这意味着：
- DB 里只存 ID 关联，省空间
- 改了某个 tool 的实现，所有引用它的 Agent 立刻生效（不用重启）
- 可以做"用户 A 的 agent 用模型 X，用户 B 的同名 agent 用模型 Y"

## 第五章 易混淆点澄清

### 5.1 short_history vs history_summary vs DialogState vs 长期记忆

四个都跟"记住过去"有关，但完全不同：

| | short_history | history_summary | DialogState | 长期记忆 |
|---|---|---|---|---|
| 范围 | 单 dialog | 单 dialog | 单 dialog | 跨 dialog |
| 形态 | 原文消息列表 | 一段中文摘要 | 几个字段 | 短事实 + 画像 |
| 存哪 | history 表 | dialog.summary | history.events JSON | ChromaDB + antang_profile |
| 触发时机 | 每次读 | token 超阈值压缩 | 每轮末尾 yield hidden 事件 | 每轮 finalize 后台写入 |

**心智记法**：
- `short_history` = "你刚才说的"
- `history_summary` = "你以前在这次聊天里说过的，被压缩了"
- `DialogState` = "我对你这次聊天的判断（情绪、阶段）"
- 长期记忆 = "你以前几次聊天中沉淀的事实和画像"

### 5.2 两个 ChromaDB 不是同一个

`data/vector_db/` 是 RAG 知识库，`data/memory_db/` 是长期记忆库。**物理隔离的两套 sqlite**，互不影响。

### 5.3 三处叫"MCP"

- `mcp_servers/` → 项目自己实现的 MCP server（被外部调用）
- `mcp_proxy/` → OpenAPI ↔ MCP 协议转换代理
- `services/mcp/` + `tools/mcp_*` → Agent 作为 MCP 客户端的封装（最常用）

做安糖业务一般只关心第三种。

### 5.4 ReAct 循环不是项目实现的

[`create_agent`](../../src/backend/AnTang/core/agents/general_agent.py#L227) 是 LangChain 提供的。要改 ReAct 行为本身（最大迭代、选 tool 策略），看 LangChain 文档，不是改本项目代码。

### 5.5 `finalize_turn` 现在不阻塞

之前是 `return None`，现在改成 `asyncio.create_task` 后台跑。所以 SSE 关闭速度不会因为长期记忆写入变慢。**但 SSE 关闭后任务还在跑**，进程关闭时如果有未完成的写入会被 cancel，可能造成 ChromaDB 状态略不一致——可接受。

### 5.6 长期记忆的两条线没合并

```
finalize_turn ─→ store_turn_memory   ─→ 只写向量库
                update_profile（未接）─→ 只写画像表
```

当前画像表永远空，长期记忆 prompt 里只有"相关历史片段"没有"用户画像"。这是预期行为。

## 第六章 我想做 X，去哪改

## 附录：术语速查

| 术语 | 含义 |
|---|---|
| **ReAct** | 让模型按"思考 → 行动 → 观察 → 思考 ..."的循环用工具解决问题。本项目用 LangChain 的实现 |
| **Agent-as-Tool** | 把一个子 Agent 包装成 BaseTool，让主 Agent 像调函数一样调它 |
| **MCP** | Model Context Protocol，跨进程的工具/资源协议 |
| **Skill** | 项目里的"技能 Agent"，本质也是一个被包成 tool 的子 Agent |
| **DialogState** | 单 dialog 内跨轮的轻量状态（情绪、阶段、上轮提问） |
| **Hidden Event** | 落进 history.events 但不暴露给前端的事件，用于跨轮持久化 |
| **AgentConfig** | Agent 的"装配清单"，全是 ID 列表 |
| **ChromaDB** | 嵌入式向量数据库，本项目用作 RAG 库和长期记忆库 |
| **light_analyzer** | 主对话之前跑的小模型分析器，给主模型一份"简报" |
| **caution_level** | light_analyzer 输出的谨慎度（normal/careful/high_attention），影响主回复语气 |
| **glucose_zone** | 当前血糖分层（severe_low / low / low_warning / normal / unknown） |
