# 本地验收心率主动关怀

这项验收不在 App 中放演示按钮，也不新增测试 HTTP 接口。下面的脚本只负责通过已有的
手环导入接口写入一页合成心率；心率规则、主动关怀 Agent、Auditor、聊天落库和手机推送
仍然由正常后台链路完成。

合成数据会永久保存在当前开发数据库。持续偏快必须使用名称以 `local_hr_high_` 开头的干净
账号，持续偏慢必须使用名称以 `local_hr_low_` 开头的另一个干净账号，不能使用平时体验或
准备保留长期记忆的账号。这个命名限制和运行前的二次用户名确认只是降低误操作概率，并不
是数据库级的绝对隔离。脚本只接受 `localhost`、`127.0.0.1` 或 `::1`，不能向远程环境写入。

运行前确认：

1. Compose 中的 API 和 `proactive-care-worker` 正常运行。
2. 专用测试账号已在 App 中填写大于或等于 18 岁的年龄。
3. 该账号已开启健康关怀和系统通知，当前不在免打扰时间；App 放在后台或锁屏。

在项目根目录运行持续偏快场景：

```bash
./api/scripts/import-test-heart-rate \
  --username local_hr_high_<自定义后缀> \
  --direction high \
  --confirm-test-account
```

脚本会要求再次输入完整用户名，再在终端中隐藏输入密码。持续偏慢要新建另一个名称以
`local_hr_low_` 开头的账号，并使用 `--direction low`。不要在同一账号里连续测试高、低
两个方向；现有规则会检查三十分钟窗口并合并间隔不超过三十分钟的 episode，混用会使结果
被判为方向冲突或重复。需要重新测试同一方向时，也优先换一个干净账号；复用账号至少等待
超过六十分钟。

同一账号、方向和十五分钟时间片会生成相同的同步编号，立即重试不会再写一份。导入接口
在重放时返回的是这个同步编号第一次处理时保存的统计，因此再次看到“新增 1 条”不表示又
新增了一条记录。脚本不会输出访问令牌或具体心率样本，并会在完成或失败后退出它新建的
临时登录会话，不影响手机 App 自己的登录。

脚本提交成功只代表测试输入已经进入正常导入接口。后续是否生成消息，应以 Worker 的真实
规则判断和数据库结果为准；运动、睡眠、近期步数、免打扰、用户刚刚发言、重复 episode 或
Auditor 拒绝都可能使本次不发送。不要为了让演示通过而直接创建任务、聊天消息或推送。
