# 华为 Band 9 的 Gadgetbridge 手动导入

## 来源与范围

PR #8 使用 Expo 的文件选择器和 SQLite 读取 Gadgetbridge 导出的数据库。解析口径根据贡献者提供的华为 Band 9 导出库校准：`HUAWEI_ACTIVITY_SAMPLE` 提供心率、步数、距离、血氧和静息心率；华为睡眠阶段、睡眠统计与压力各有独立表。这个口径不能推断到其他厂商或所有华为机型。

导入界面中的图表是这次所选文件的预览。上传到服务器的观测才会进入健康档案和历史查询。卡路里与压力暂不属于后端可穿戴观测类型，只在本地预览。Zepp 经 Health Connect 的自动同步继续独立运行。

## 本次合并检查

- 只接受有数据的华为活动表；同一个导出文件的活动、睡眠、压力行必须只有同一组 `DEVICE_ID` 与 `USER_ID`。设备名按对应 `DEVICE._id` 读取。
- 每种记录分批调用既有手环导入 API，上传请求只含一种记录类型。再次导入同一数据时按记录 ID 与内容去重；导出文件的修改时间用于区分后续更正。
- 两种来源可能属于不同手环。主动心率规则只在各自来源内部组合心率和活动上下文。Gadgetbridge 文件没有经过验证的完整运动上下文，导入时不能声明 `health_context_complete`。
- Android SQLite 原生依赖需要新 APK。导出数据库的表结构与当前真机上的文件仍需在新包中验证；静态检查和模拟数据库测试不能代替真机导入验收。

## 待验证

在一份真实华为 Band 9 导出库上核对解析数量、睡眠阶段、上传数、重复导入结果，以及服务器按来源显示的观测。若今后一个账号导入多台 Gadgetbridge 设备，记录 ID 必须加入设备标识，避免同一时刻不同设备的记录相互覆盖。
