# 旧项目功能盘点

这份记录只回答三个问题：旧项目已经具备什么产品能力，当前实现怎样串起这些能力，重写时哪些问题需要直接清除。它用于确定新版产品范围，不代表新版架构方案。

## 已存在的用户能力

以下内容来自 `../AgentChat` 的前后端接口、页面和服务源码。

- 账号：注册、登录、个人资料、昵称、简介、头像。
- 对话：新建、重命名、删除和查看历史会话；回答采用流式输出；用户可以中止生成。
- 消息附件：上传图片或文件，并在对话中交给模型理解。
- 血糖上下文：用户可以在发消息时填写当前血糖值和变化趋势。
- CGM 报告：上传 PDF、CSV 或截图，查看导入记录和原文件，删除报告，调用 Agent 解读最近一次报告。
- 糖尿病知识问答：检索本地专业资料；另有 LightRAG 图谱检索入口。
- 生活管理：饮食建议、运动建议、食物营养与 GI 查询。
- 提醒：通过对话创建、查看和取消提醒；到点后生成消息并进入通知收件箱。
- 主动联系：结合待跟进任务、血糖风险和设备断连等事件，主动向用户发送消息。
- 长期记忆：Hindsight 召回用户记忆；后台记忆审查流程从近期对话中提取长期信息。
- 回答审核：部分消息经过风险探测、资料评估、回答审核和后续问题规划。
- 用户反馈：对回答点赞或点踩。
- 通用工具：联网搜索、天气、图片生成和北京时间查询。

## 当前 Agent 链路

普通消息可以直接进入主 Agent。风险探测器判定需要专业评估时，链路会经过“风险探测 → 资料评估 → 主 Agent → 回答审核”，审核未通过会再次生成一次回答。回复完成后，系统可能创建可点击的后续问题、安排主动跟进，并在后台审查是否写入 Hindsight。

主 Agent 暴露了 16 个工具，覆盖知识检索、图谱检索、联网搜索、天气、图像理解、饮食、运动、CGM、提醒、食物营养和图片生成。工具数量和业务跨度都很大，职责边界已经模糊。

## 当前数据与基础设施

- 后端：Python、FastAPI、LangChain、SQLModel。
- 前端：Vue 3、TypeScript、Vite、Element Plus。
- 业务数据：MySQL。
- 临时状态和后台任务协调：Redis。
- 文件：MinIO，也保留了 OSS 配置。
- 文档检索：Elasticsearch 关键词检索、Milvus 向量检索、查询改写、RRF 融合和 rerank。
- 图谱检索：独立 LightRAG 服务。
- 长期记忆：独立 Hindsight 服务。
- 部署：Docker Compose，完整环境包含 MySQL、Redis、Elasticsearch、Milvus、etcd、两套 MinIO、LightRAG、Hindsight、前后端。

## 新版产品范围

本盘点当时形成的初步归类已经由项目根目录 `AGENTS.md` 中的正式首版范围取代；本文只保留旧实现证据，不再同时维护一份当前计划。

## 旧实现的淘汰清单

以下行为与新版已经确认的“尽早暴露问题”规则冲突：

- 风险探测模型返回空结果后，使用关键词和阈值启发式继续判断。
- 回答审核模型返回空结果后，自动判定审核通过。
- Hindsight 召回失败后，使用空记忆继续生成回复。
- 主动消息生成失败后，发送静态兜底文案。
- 多处后台任务捕获异常、记录日志后继续运行。
- CGM 解析失败时，接口可能仍以成功 HTTP 状态返回业务失败结果。
- 知识索引在启动后台异步建立，服务可在资料尚未就绪时接收请求。
- 一次审核失败只触发固定的一次重试，仍缺少清晰的终止状态与用户可见错误。

新版需要统一采用显式失败、清晰状态和可追踪原因。具体错误协议、任务状态与恢复方式留到完整方案阶段设计。

## 盘点结论

旧项目验证过一组较完整的产品想法，也暴露了职责过宽、静默降级和基础设施过重的问题。新版的当前范围与进度统一以项目根目录 `AGENTS.md` 为准。
