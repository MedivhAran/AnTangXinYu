# 控制一般 / 有改进空间 - 输出脚本

适用条件:TIR 在 (tir_threshold_pct - 20%, tir_threshold_pct) 之间,或 tbr_pct 在 4%-10%。

## 总体段落写法

> 这段时间(YYYY/MM/DD ~ YYYY/MM/DD,N 天)控制处于"还可以再改善"的水平。
> TIR X%(目标 ≥ Y%),距离达标还有 (Y-X) 个百分点。

**不要**用"不及格""失败"这类词。

## 关键数值看点

- TIR vs 目标的差距(具体百分点)
- TBR(如果在 4-10% 区间,要单独点出,说明低血糖发生比目标偏多)
- TAR(高于目标的时长 - 通常是改进重点)
- CV(如果 > 36%,说明波动偏大,稳定性比绝对值更值得关注)

## 值得关注的细节

这是"需要改进"档位的**核心段落**,要给具体观察。从 daily_metrics 和 hourly_metrics
里找 1-3 条线索:

- 哪几天 TIR 明显低?(列日期 + 数字)
- 哪个时段 TAR / TBR 集中?(比如 "08-10 这段时间 TAR 经常 > 40%")
- daily_metrics 里有没有"控制特别好的一天" + "控制偏差的一天"对比 - 帮用户自己找规律

## 我的建议

**3-4 条**,**小颗粒度**。不要写"加强饮食控制"这种没有信息量的话。

可以包含的方向:
- 餐后 1-2 小时血糖偏高 → 建议下次记录 1-2 顿饭看看是哪类食物的影响
- 夜间血糖偏低 → 建议睡前少量加餐,跟医生确认睡前胰岛素剂量
- 波动偏大 → 建议固定主餐时间,减少加餐次数
- TBR 偏高 → 建议医生处复盘剂量,先不要自己调

**每条建议都要包含**:
- 一个**可以这周就做的具体小动作**
- 涉及用药/剂量的,必须加"建议跟医生确认"

## 语气

平视、不评判。说"我们一起看看哪里可以再优化",不要说"你需要做..."。
